Abstract

We demonstrate Ontosphere, a zero-install, browser-based semantic web workbench that combines OWL 2 DL reasoning, SHACL validation, visual graph authoring, and AI-agent integration in a single client-side application. The demonstration walks through a data-quality correction workflow using the Platform MaterialDigital Core Ontology (PMDco): loading a chemical-composition dataset, classifying it with the Konclude reasoner compiled to WebAssembly, discovering a SHACL violation activated by reasoning-derived types, correcting the data through visual authoring, and exporting the validated result. The entire workflow executes in the browser without server infrastructure. A screencast (~4 min) and the live system are publicly available.

Introduction

Quality assurance for ontology-conformant data in materials science requires both logical reasoning (to infer implicit types) and constraint validation (to check data shapes). These operations traditionally depend on desktop tools like Protégé [8] or server-hosted platforms, creating friction in collaborative and educational settings.

Ontosphere [1] addresses this by running a complete OWL 2 DL reasoner (Konclude [2], compiled to WebAssembly) alongside SHACL validation and visual graph authoring in a single browser tab. In this demonstration, we show how reasoning-activated SHACL constraints expose data-quality gaps that would remain hidden without classification, and how domain experts can correct these gaps interactively.

System Overview

Ontosphere (v1.7.2) is a Vite-bundled React single-page application in which all computation occurs client-side. Its architecture comprises:

  • N3.js quad store [3] — five principal named graphs (asserted data, loaded ontologies, inferred triples, SHACL shapes, PROV-O provenance).
  • Konclude WASM reasoner [2] — full SROIQ(D) classification in a SharedArrayBuffer-backed Web Worker, with laconic justifications [7] for inconsistencies and arbitrary entailments, plus axiom-weakening repairs.
  • SHACL validation via shacl-engine [6] — executes automatically after OWL inference; inferred triples are materialised into the store before validation, ensuring that reasoning-derived types are subject to shape constraints.
  • Reactodia canvas [4] — visual graph editor with always-on authoring, TBox/ABox views, and halo-drag edge creation.
  • 42-tool MCP server [5] — exposes all operations to AI agents via the Model Context Protocol, with PROV-O provenance tracking.

Demonstration

The demonstration (screencast, ~4 min) follows a data-quality correction story using real-world materials-science data from the PMD Core Ontology (PMDCO). The live system is available at https://thhanke.github.io/ontosphere/.

The workflow proceeds in five steps:

  1. Load. The presenter opens Ontosphere with a ?url= parameter pointing to a PMDCO chemical-composition dataset describing a silicon–iron alloy. Labels are resolved via the ontology autocomplete registry, and bundled SHACL shapes for ontology quality checking are loaded.
  2. Classify. Konclude classifies the PMDCO hierarchy. The silicon portion (some_silicon) is inferred to be a pmdco:Semiconductor based on its material composition — a type not explicitly asserted in the source data. Inferred triples appear as amber dashed edges on the canvas.
  3. Validate. SHACL validation runs automatically after reasoning. Because some_silicon is now typed as a pmdco:Semiconductor, a previously inactive shape constraint activates and reports a violation: the required has quality relationship is missing.
  4. Correct. The presenter creates a new quality class and individual via visual authoring, then draws the missing has quality edge using a halo drag. This is a domain-expert correction — only a materials scientist can decide what quality to assign.
  5. Export. Re-running reasoning confirms all constraints are satisfied. The corrected dataset is exported in Turtle, JSON-LD, or RDF/XML, preserving both the expert’s asserted correction and the reasoner’s inferred classification.

The key insight is that reasoning and validation are complementary: OWL classification reveals implicit types, which in turn activate SHACL constraints that expose data-quality gaps invisible to validation alone.

Availability

Ontosphere is deployed at https://thhanke.github.io/ontosphere/ and released under the Apache 2.0 licence. Source code is available at https://github.com/ThHanke/ontosphere. Per-feature screencasts cover loading (68 s), exploration (90 s), authoring (103 s), clustering (43 s), reasoning (141 s), SHACL (85 s), and AI relay (65 s).
